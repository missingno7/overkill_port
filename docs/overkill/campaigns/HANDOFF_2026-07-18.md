## 1. THE ONE-PARAGRAPH STATE

OVERKILL's generated CPUless corpus is **623/626 promotable with ZERO overrides**. The top level
`1010:96C8` — the main loop that sequences front-end -> level select -> gameplay — **now promotes**,
and the runtime closure from the gameplay frame root `1010:97B2` is **253/253 with an empty
frontier**. The three remaining refusals are structural, not capability gaps (§3b).

**Do not read that as "the port runs."** Promotion bought CLOSURE, not EXECUTION. The ten top-level
entries are promoted STANDALONE-ONLY, nothing calls them through the CPU ABI, and
`coldboot_frontier.py` output is byte-identical to before. OVERKILL still has **no frame-indexed
cold-start differential**, and that — not promotion — is now the gap. §9 is the whole next task.

## 2. THE METHOD (adopted 2026-07-18, do not deviate)

Grow ONE continuous oracle-proven path from cold boot. Boot the recovered program, let it run until
it hits something the port has not supplied, repair THAT seam, rerun from frame zero. The earliest
divergence is the frontier; do not investigate functions out of order or patch likely-looking areas.

Instrument: `scripts/coldboot_frontier.py`. `FailLoudPlatform` names the missing service and the
corpus never falls back to a VM, so **the exception IS the report**.

Why this replaced call-graph analysis: graph work produced real results but also two wrong turns a
cold boot could not have made — naming `0B3E` as the DOS-I/O seam when it performs no DOS I/O at all,
and a ten-function island set where four were needed and six were ordinary game code.

## 3. WHAT LANDED — setjmp/longjmp representation (dos_re `4dcf7d0`)

`emit_cpuless` can now REPRESENT setjmp/longjmp. Two recognisers, deliberately asymmetric:

* **`_is_nonlocal_exit`** (`emit_cpuless.py:1443`) — `mov sp, m16` (op `0x8B`, reg field 4, modrm
  memory) whose every forward path falls straight into a `ret`. This is a longjmp RESTORE: the return
  happens on a stack frame the function never established. It is **TERMINAL** — a fail-loud raise, no
  exit ABI recorded, the depth walk stops there — exactly as a runtime-dead exit is.
* **`_is_sp_snapshot_store`** (`emit_cpuless.py:1425`) — `mov m16, sp` (op `0x89`) is PERMITTED, on a
  narrow argument: the CPUless ABI keeps `sp` exact, so storing it is an ordinary exact store of a
  tracked value. Restricted to a MEMORY destination; `mov r16, sp` still refuses `sp-as-data`.

**The unwind is DELIBERATELY NOT MODELLED.** Reproducing it means asserting which frame the longjmp
lands in and what it returns there — a contract that must be RECOVERED from the paired setjmp site,
never guessed to make promotion pass. Until such a site is modelled **the raise IS the frontier
witness**. In both corpora seen so far these tails are C-runtime fatal-abort paths that normal
execution never takes, so the raise costs nothing on the real path. If you ever see one fire, that is
a genuine finding, not a bug to suppress.

Census, before -> after:

| bucket                      | before | after |
|-----------------------------|--------|-------|
| promotable                  | 591/626 | **623/626** |
| `contains-call`             | 20     | **0** |
| `boundary-head-on-transfer` | 10     | **0** |
| `sp-as-data`                | 2      | **0** |
| overrides                   | 0      | **0** |

Emitted raises live in `func_1010_0111 / 0248 / 0624 / 065c`. `func_1010_0011` carries the SAVE side
only.

### 3a. HOW THE PREVIOUS §3 WAS WRONG — read this, it is the lesson

The previous handoff claimed `96C8` was blocked by a **SINGLE** dos_re capability gap at `1010:065C`.
That was wrong in four ways, and the mechanism behind the error is the reusable part:

1. **There were FIVE terminal blockers, not one.** A real FIXPOINT over `96C8`'s transitive closure
   found `1010:0011`, `1010:0111`, `1010:0248`, `1010:0624`, `1010:065C`. Overriding `065C` alone
   unblocked only itself: `contains-call` went 20 -> 19.

2. **A cascade refusal MASKS a function's own terminal refusal.** `contains-call` is raised at
   `emit_cpuless.py:995`, BEFORE the `sp-as-data` check at `:1061`. So a function that has its OWN
   terminal blocker, but also calls something already refused, reports only `contains-call` — its
   real blocker never surfaces. **A one-pass census therefore UNDERSTATES the blocker set.** Each
   override you add surfaces the next layer. This is exactly the trap the previous handoff's own §5
   warned about ("a one-pass reachability walk read as a fixpoint") — and then fell into.

3. **The proposed fix was INCOMPLETE.** It specified recognising `mov sp, m16` only. That leaves the
   setjmp SAVE side `mov m16, sp` (op `0x89`) refusing at `0011` and `0248`, so `96C8` would still
   have refused, with two newly-surfaced blockers. Both directions were needed, and they needed
   OPPOSITE treatments (terminal raise vs. permitted store) — see §3.

4. **The universality claim was unsupported.** It asserted "every DOS C runtime has this shape."
   Measured: **skyroads has zero instances across 9,245 instructions; lemmings zero across 22,739.**
   It is a real dos_re capability gap that only THIS game happens to exercise. Still the right place
   to fix it — a general lifter should represent a general construct — but for the right reason, and
   without pretending the other ports were waiting on it.

**Detail corrections to the old §3's disassembly:**

* The `mov sp, cs:[0242]` is at **`02BC`**, not `02B2`.
* `02B2` first does `push ax; call 065C; pop ax` — so `065C -> 02B2 -> 065C` is a **cycle**.
* It loads DS with a **CONSTANT `25CCh`**; it does not "restore" DS.
* **`1010:0615` was never a blocker** — pure cascade. It is promoted now with no raise in it.
* There are **TWO independent saved-sp slots** (`cs:[0242]` and `ds:[000E]`). No recogniser may key
  on a single cell. The shipped one keys on the instruction FORM, not the address, which is why it
  covers both.

## 5. NEGATIVE EVIDENCE — do not re-run these dead ends

Preserved deliberately; each cost real time.

* **`--desmc` for `1010:0248`.** Hypothesis: self-modifying code. FALSIFIED — bytes identical across
  all three snapshots. The real cause was a probe bug (below).
* **`--observed` (execution evidence -> dead exits).** Regresses promotion: 591 -> 571 promotable,
  `contains-call` 20 -> 40. My first explanation was "not enough demo coverage"; **that was falsified**
  — unioning to 59% coverage produced a BYTE-IDENTICAL census. Real mechanism: dead-exit marking is
  SUBTRACTIVE. 168 functions have every `ret` unexecuted, lose their exit ABI, and callers cascade to
  `contains-call`; 20 lost, 0 gained, all transitively. More demos cannot fix it (the `1F8F`
  sound-driver segment shows 18 executed addresses across all three recordings). Kept in
  `scripts/capture_observed_trace.py`'s docstring beside the numbers that killed it, because "union
  more demos" is the obvious next move and would cost a day.
* **Probe self-corruption, first test.** The hypothesis was right but the first reproduction did not
  fire; it only reproduces inside a full scan, not when probing addresses in isolation.
* **A one-pass reachability walk read as a fixpoint.** Overstates what stays blocked. THREE wrong
  turns came from this now, including the previous §3 (see §3a.1–2). **Use a real fixpoint, and
  remember that an earlier refusal check masks a later one** — re-census after every override.
* **"Every DOS C runtime has this shape."** Asserted without measurement, false when measured (§3a.4).
  Before generalising a construct across ports, COUNT it in the other corpora — both are checked out
  next door and the count takes minutes.
* **Localizing a divergence inside the candidate before proving the reference side.** See §7: an
  entire claimed frontier turned out to be the ORACLE deviating from the original program.

## 6. LANDMINES — things already fixed, do not re-break

* **The CPUless import guard is PROCESS-GLOBAL.** A bare `install_import_guard()` in a test arms the
  wall for the whole session; it cost 239 red tests that each PASSED in isolation and looked exactly
  like corpus drift. Use `overkill.cpuless_host.import_guard()` (scoped). `tests/conftest.py` has an
  autouse ratchet that fails the leaking test by name.
* **The stitch needs three things, not one.** `sys.modules` shadowing ALONE misses (a) callers that
  already imported the callee by direct reference and (b) `_dyncall`'s warmed resolution cache. Both
  silent. `install_overrides` retro-patches and clears the cache; `uninstall_overrides` restores. Do
  not "simplify" it back. Also: the retro-patch must SKIP `...__generated` oracle aliases, or the
  differential compares an override against itself and still passes.
* **`pathlib.read_text()` defaults to cp1250 here.** Always pass `encoding="utf-8"`.
* **`threading.stack_size(512MB)`** raises on Windows; 64MB is the portable ceiling.
* **`test_cpuless_host.py::test_unpromoted_function_fails_loud` uses `1010:3EFC`.** It used to use
  `1010:97B2`, which this session PROMOTED, killing the premise. `3EFC` was chosen because its
  refusal is STRUCTURAL (an undecodable byte sequence, §3b) — a future lifting capability cannot
  promote it, so the example will not rot the way a missing-capability frontier does. If you promote
  it anyway, re-point the test at another structural refusal; **do not delete or relax it.** The
  property is: an address with no recovered module raises `CpuStandaloneWitness`, never falls back.
* **`audit_recovery_facts.py` proves boundary-head consumption POSITIVELY.** It used to infer "this
  fact was consumed" from the PRESENCE OF A REFUSAL in the `boundary-head-on-transfer` bucket. That
  inference is backwards, and this session's improvement exposed it: the bucket emptied because the
  head COMPOSED, and the audit read that SUCCESS as an unconsumed fact. It now requires the declared
  head address to literally appear in an emitted `plat.boundary(cs, ip, ...)` call in the committed
  corpus (COMPOSED case) **or** in the refusal bucket (REFUSED case) — true in both outcomes, and
  per-head rather than aggregate. **Never re-key a consumption check on a failure signal.**

## 7. dos_re — the shared framework (coordination surface)

Both ports consume `dos_re` (currently `abi-recovered`). Landed from OVERKILL this session:

* **setjmp/longjmp representation** — §3. This is the big one.
* **`registry.uninstall(cpu, keep=...)`** and **`assert_pure_oracle(cpu, allow=...)`**
  (`dos_re/hooks.py:64`, `:95`); `create_runtime(install_replacements=False)` is now honoured via a
  **POST-BOOT STRIP** (`dos_re/runtime.py:125`) — install, then strip from the registry.
  * **OVERKILL already had this right**: `overkill/runtime.py:47` strips after boot for exactly this
    reason. The framework now OWNS the mechanism the port had reimplemented; `overkill/runtime.py`'s
    docstring is now slightly stale (it says dos_re dropped the flag) but the behaviour is correct.
  * **Why it matters beyond tidiness**: skyroads was guarding the hooks **IMPORT** instead, which
    does not work — the registry is populated at DECORATION time, any other import in the process may
    already have pulled the module in, and `install()` then wires it onto the "pure" CPU anyway. It
    had **29 replacements live on its supposed pure-ASM oracle, including a deliberately
    behaviour-changing loop-skip optimisation.** Its entire claimed frame-1115 frontier was the
    ORACLE deviating from the original program, not the candidate.
  * **General lesson (also in §5 and §10): before localizing a divergence inside the candidate, PROVE
    the reference side is the original program.** `assert_pure_oracle` exists so a harness can say so
    and get an exception naming the offenders instead of a plausible wrong answer.
* `lift/probe.py` (`612cb2f`) — **the IP-delta probe was corrupting the code it measures.** It executes
  each candidate instruction with meaningless registers, so a store lands in the code segment and later
  probes decode the wreckage; the tell was `interpreter-delta=3` (a 3-byte `cmp ax,imm16` from
  scribbled `3D FF`) for instructions of length 5, 2, 2. Produced FALSE `decoder-mismatch` refusals.
  `liftgen` and `irgen` had independent copies; both now delegate. **SkyRoads inherits this — any
  `decoder-mismatch` refusal there is worth re-measuring.**
* `lift/standalone.py` — `uninstall_import_guard()` + `import_guard()` context manager.

**Rule for this run:** anything game-agnostic (shadow verification, contract composition, adapter
generation, refusal taxonomy, virtual-time handling) goes INTO dos_re so the other game inherits it.
Do not deform the general lifter to encode a one-game pathology; prefer a bounded VERIFIED_OVERRIDE or
a platform service. Note that §3a.4 is the counter-check on this rule: "general" must be MEASURED, not
assumed — the setjmp work was still right to land in dos_re, but because the construct is general, not
because the other corpora needed it.

## 10. STANDING RULES (project invariants, non-negotiable)

* Never commit red; full `python -m pytest -q` green before every commit.
* One verified slice = one focused commit + push to `main`.
* Never weaken an oracle/test/assertion to make a slice pass. If a test's PREMISE goes obsolete
  because you IMPROVED something, re-point it at a premise that is still true and still tests the same
  property — do not delete it, relax it, or xfail it. Both of this session's test changes are
  re-pointings of that kind (§6).
* **Before localizing a divergence inside the candidate, PROVE the reference side is the original
  program** (`assert_pure_oracle`). A contaminated oracle does not fail — it reports a wrong frontier
  and sends you after a defect the candidate does not have (§7).
* **Use a real fixpoint, and re-census after every override**: an earlier refusal check masks a later
  one, so a one-pass census understates the blocker set (§3a.2).
* **Measure before generalising across ports.** "Every X has this shape" is a claim with a cost; both
  sibling corpora are checked out and countable (§3a.4).
* Failed attempt => full revert + a repro line in `loop_blockers.md`.
* Fail loud, never fake a gap. A raise at an unmodelled construct IS the deliverable, not a defect.
* Check the STANDING MECHANISMS registry at the top of `run_status.md` before building any tooling.
* State claims NARROWLY: "proven for this demo, to this reached frontier" — a passing local island is
  not proof of the whole path, and **a promoted corpus is not a running game** (§1, §9).
