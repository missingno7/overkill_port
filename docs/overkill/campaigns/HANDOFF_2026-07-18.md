## 1. THE ONE-PARAGRAPH STATE

OVERKILL's generated CPUless corpus is 591/626 promotable and byte-identical on regeneration. The
game's own logic is essentially all promotable; what is missing is the TOP LEVEL — `1010:96C8`, the
main loop that sequences front-end -> level select -> gameplay. It is blocked by a single dos_re
capability gap (a C-runtime longjmp at `1010:065C`). Until that lands, the CPUless build cannot run
the cold-start path at all, so **no frame-indexed cold-start differential exists yet**. The boot
bootstrap `254A:04D7` DOES run to completion standalone on dos_re's `DOSMachine`.

## 2. THE METHOD (adopted 2026-07-18, do not deviate)

Grow ONE continuous oracle-proven path from cold boot. Boot the recovered program, let it run until
it hits something the port has not supplied, repair THAT seam, rerun from frame zero. The earliest
divergence is the frontier; do not investigate functions out of order or patch likely-looking areas.

Instrument: `scripts/coldboot_frontier.py`. `FailLoudPlatform` names the missing service and the
corpus never falls back to a VM, so **the exception IS the report**.

Why this replaced call-graph analysis: graph work produced real results but also two wrong turns a
cold boot could not have made — naming `0B3E` as the DOS-I/O seam when it performs no DOS I/O at all,
and a ten-function island set where four were needed and six were ordinary game code.

## 3. THE FRONTIER — the exact next task

`1010:96C8` has no recovered module. Chain: `96C8` -> `9B2E` -> `4DBF` -> `0B3E` -> `C679`/`0248` ->
`0615`/`0624`/`065C`. Bottom: **`1010:065C` refused `sp-as-data`**.

`065C` is DOS close-file; on error it jumps to `02B2`, which restores DS, does `mov sp, cs:[0242]`
— restoring a saved stack — sets carry and `ret`s, returning on the RESTORED stack. That is a
**C-runtime fatal-abort longjmp**, not an OVERKILL quirk: every DOS C runtime has this shape. Fix it
in dos_re, not locally.

`emit_cpuless` already has the right precedent in its RUNTIME-DEAD-EXIT handling: terminal, constrains
nothing, emits a fail-loud raise instead of a return. A longjmp is the same idea with a real cause.
**Four sites, all located:**

1. `~1396`, beside `_is_bootstrap_ss_switch` — add `_is_nonlocal_exit(scan, i)`: `mov sp, m16`
   (op `0x8B`, reg field 4, modrm memory) where every forward path reaches a `ret` with no
   intervening push/pop/call. Recognise TIGHTLY, exactly as the precedent does.
2. `~1053` — `continue` instead of `raise Refusal("sp-as-data")` when it fires.
3. `~1508` in `_check_stack_depths` — treat that `ret` as `dead_exits` does (no depth, no `ret_pop`).
4. `~2000` block emitter — emit a structured `NonLocalExit` raise, terminating the block.

A Python exception is the natural model: it unwinds the interpreter stack the way the original unwinds
the machine stack. Caught at the recovered program root (or a future setjmp site).

After it lands: rerun `coldboot_frontier.py`, then run the cold-start differential over the two spine
demos and let the first divergence pick the next task.

  all three snapshots. The real cause was a probe bug (below).

* **A one-pass reachability walk read as a fixpoint.** Overstates what stays blocked. Two wrong turns
  came from this; use a real fixpoint.

## 6. LANDMINES — things already fixed, do not re-break

* **The CPUless import guard is PROCESS-GLOBAL.** A bare `install_import_guard()` in a test arms the
  wall for the whole session; it cost 239 red tests that each PASSED in isolation and looked exactly
  like corpus drift. Use `overkill.cpuless_host.import_guard()` (scoped). `tests/conftest.py` has an
  autouse ratchet that fails the leaking test by name.
* **The stitch needs three things, not one.** `sys.modules` shadowing ALONE misses (a) callers that
  already imported the callee by direct reference and (b) `_dyncall`'s warmed resolution cache. Both
  silent. `install_overrides` retro-patches and clears the cache; `uninstall_overrides` restores. Do
  not "simplify" it back. Also: the retro-patch must SKIP `...__generated` oracle aliases, or the
  differential compares an override against itself and still passes.
* **`pathlib.read_text()` defaults to cp1250 here.** Always pass `encoding="utf-8"`.
* **`threading.stack_size(512MB)`** raises on Windows; 64MB is the portable ceiling.
