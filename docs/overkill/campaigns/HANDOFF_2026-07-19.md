## 2. THE METHOD (unchanged, do not deviate)

Grow ONE continuous oracle-proven path. The FIRST divergence is the frontier and nothing else is
in scope. Localize the earliest differing *observable*, instrument the routine that ACTUALLY
produces it, repair only that seam, rerun from frame 0. The frontier advances only if the earliest
divergence moves.

Two rules this session repeatedly earned:

* **Run an UNGATED control first.** A windowed aggregate reading zero is indistinguishable from
  "never happened". Every forward inference from partial instrumentation was wrong; every added
  control was right.
* **Compare STREAMS, not SUMS.** A totals-only check accepts a uniform ×2 that is perfect on the
  calibration path and wrong in mechanism (§6).

## 3. THE FRONTIER — the exact next task

OVERKILL's spine demo cannot run because **the candidate has no way to observe a keypress**:

    INT 09h vector -> 1010:4ED2   NOT in the closed set, no module, refuses `mixed-return-kinds`
    INT 08h vector -> 1010:06E5   promoted (which is why the timer path works)

**The refusal is CORRECT and must not be relaxed.** Diagnosed in `ad31824`:

    1010:06E5 (INT 08h, PROMOTES): exits ['iret','jmp_ind']         7 blocks, 0x4D bytes
    1010:4ED2 (INT 09h, REFUSES) : exits ['iret','jmp_ind','ret']  25 blocks, 0xF48 bytes

The ISR itself is tiny — `4ED2..4F36`, six blocks: save regs, read 60h, ack the 8042, update the
key-state table at `98C4`, EOI, restore, iret. But one conditional restores all registers and does
`jmp near 5D14`, and **the scan follows that tail and swallows `5D14` whole** — 19 foreign blocks
contributing `ret` at `5E14` and `jmp_ind` at `5DFD`. `iret` + `ret` in one function really are two
incompatible ABIs (IRET pops FLAGS as well as CS:IP), so relaxing the check would be hidden
unsoundness. 06E5 stays clean because its second exit is a *chain* (`FF /5` far indirect through
the saved vector) which `_is_isr_chain` recognises and which TERMINATES the scan.

`1010:5D14` is a **jump-only shared continuation, never called** — reached from `4ED2@4F1D`,
`5559@55D2`, `558B@55D2`. `5559`/`558B` absorb it too and promote fine, because their own exit is
`ret`, so `ret+ret+jmp_ind` is homogeneous. Only the ISR mixes kinds.

**CLASSIFICATION: the SCAN BOUNDARY, not the exit check.** Precedent: the manufactured-return fix
(`f23b0fb`/`47ca790`) was exactly a case where `scan_function` stopping in the wrong place made a
downstream check fire on the wrong thing.

**The fix**: represent `5D14` as a shared tail continuation — its own recovered function that the
three tail-jumpers transfer to — so `4ED2` keeps a clean `iret` contract and `5D14` keeps its own
`ret` contract. Tight and general, in the manner of `_is_bootstrap_ss_switch` / `_is_nonlocal_exit`
/ `_manufactured_return`: recognise the construct, refuse loudly on anything not positively
recognised, never fall through to a silent assumption.

**TWO THINGS MUST BE MEASURED BEFORE IMPLEMENTING:**

1. What the ISR path through `5D14` does with the CPU-pushed IRET frame. `5D14` does `sti`,
   silences the speaker, restores mode 3 and prints via INT 21h AH=09 — it *reads* as the QUIT
   path, so the `ret` may be unreachable from the ISR. **Establish that by RUNNING it**, not by
   reading.
2. Splitting `5D14` out also changes `5559` and `558B`. It needs the same before/after
   **promotable AND parking AND ledger** measurement `C9FC` got (§5).

### After it lands — the dependency chain (all prerequisites already validated)

    5D14 represented -> ISR promotes -> input delivery -> gameplay-path clock check -> SPINE RUN

* **Input delivery**: 133 events to BOTH machines at matched recorder-rule boundary indices via the
  now-promoted recovered INT 09h ISR. Model: `skyroads_port/scripts/verify_cpuless.py` `deliver_key`
  (set scancode, mark buffer full, fill the BIOS type-ahead buffer, run the game's own ISR). Input
  for frame N applied BEFORE frame N renders.
* **Gameplay-path clock check**: the clock agreement in §4 is proven on the ATTRACT path with zero
  input. **Do not let the gameplay path inherit it.** Re-run the frame-for-frame check with input
  driving before trusting any spine number.
* **The spine run** drives the gameplay path for the first time. Expect divergences — a divergence
  is a GOOD result and is the first frame-indexed evidence anyone has about OVERKILL's gameplay
  spine under CPUless.

## 4. THE DEMO AND THE CLOCK (solved; do not re-litigate)

`artifacts/demos/demo_coldspine_20260718_211150` — owner-recorded, **true cold start**
(`snapshot: None`), 133 events, `end_boundary` 2497, config `tandy`/`adlib`/tail `\r\x02A`.
Menu → Level 1. It replays end to end under the frame verifier, 133/133 events applied.

**The boundary stream is DETERMINISTIC from VM state.** Proven empirically, not by code reading: a
**48×** wall-clock spread produces a byte-identical stream (16426 boundaries), and a **2.7×** spread
with all 133 events delivered produces an identical sha1 across three arms. The async timer IRQ was
genuinely exercised (47 vs 8652 ISR deliveries) and the stream did not move. Reason: *a boundary is
a CALL, and the call count is control-flow determined* — extra ticks only shorten each spin.

**THE CLOCK MAPPING — read this before touching it.**

`differential frame = boundary - 410` is **arithmetically impossible** and was refuted by
measurement. Measured on the differential's own oracle: `{1839: 1, 3: 299}` boundaries per frame.
Offset-only requires ratio 1; it is 3 in steady state. Structural, not tuning: the recorder counts
every `0679` call, the differential cuts on the 2nd pass at `0679`, so one differential frame is at
minimum two recorder timer-boundaries.

The 1:1 result that produced that wrong spec holds **only** between the frame verifier's frame
counter and the recorder's boundary counter (both retrace-driven). **It does not transfer to the
differential's cut.** Scope is now recorded so the misreading is not available.

**THE ADOPTED SOLUTION (validated, `dae2cbf`)**: count recorder-rule boundaries LIVE on both sides.
Exact, not derived. Host-side observation via `install_overrides` shadowing, each override
delegating to `generated(addr)` and returning its result untouched — **not** a new boundary head.

    ORACLE    (cs:ip arrivals)    : {retrace 1836, present 300, timer 600}
    CANDIDATE (corpus's own calls): {retrace 1836, present 300, timer 600}   IDENTICAL, 300 frames

Counters proven behaviour-neutral: 9000-frame attract differential PASS with counters live at
`{retrace 15156, present 9000}` — totals reported *because* a gate that passes on an inert
instrument proves nothing.

Also solved: `1010:58F4`, long documented as an inexplicable "mid-function resume", is simply
**boundary 1 of a cold boot** (the return site of the first `call 50C9`).

## 5. NEGATIVE EVIDENCE — do not rediscover

Each cost real time.

* **`254A:04D7` is NOT the C-startup bootstrap.** It is the asset-container overlay-open (far-called
  by `1010:0248`/`C679`, returns a file handle). "BOOT ROOT RAN TO COMPLETION" was always vacuous.
  Docs corrected.
* **A true cold boot is out of reach.** Real cold entry is `1C32:000E`, the **LZEXE stub**. Segment
  `1C32` has zero census entries and zero corpus modules — the corpus cannot run the decompressor
  that produces the program it lifts. Lifting it is real, separate work; make it a deliberate
  decision, not a side quest.
* **`1010:C9FC` (the real retrace polling site) is DECLINED.** The address is right — the `50C9`
  thunk's 623→585 regression is refuted — but it is **not free**: parking goes 20 → 42, i.e. 22
  functions lose CPU-ABI adapters, six of which carry (INCONCLUSIVE) ledger verdicts and become
  permanently unprovable by the per-function differential. Both halves of the trade sit beside the
  declaration in `lift_boundary_heads.txt`.
* **`close_census.py`'s liftable count and `cpuless_promote.py --apply`'s parking count are
  DIFFERENT COST FUNCTIONS.** Reading one as the other is what made C9FC look free. Always measure
  both.
* **Re-indexing demo events by a measured distribution is wrong**, not merely disallowed: retrace
  freezes at 1836 on the input-free path while the spine stream is `{retrace 1532, timer 171}`, so
  a factor fitted on attract does not hold on the spine.
* **`--observed` (execution evidence → dead exits) regresses promotion.** Dead-exit marking is
  SUBTRACTIVE; more demos cannot fix it. Numbers in `scripts/capture_observed_trace.py`'s docstring.
* **A one-pass census is not a fixpoint.** `contains-call` is raised BEFORE the later terminal
  checks, so a cascade refusal MASKS a function's own terminal refusal. Three wrong turns came from
  this. Use a real fixpoint.

## 6. TRAPS — general, and in the standing-mechanisms registry

* **A corpus function's CALL count is not its ARRIVAL count.** A generated body is a `while True:`
  block dispatcher: internal poll loops re-arrive without a new call, and inlined near-JMP targets
  have no call at all. This bit twice — `func_1010_bd17` (reads 0, means nothing) and `0679` (2:1
  disagreement). For a declared head, count `plat.boundary`, not calls.
  **Method that catches it:** frame-for-frame comparison of two independently-counted streams.
  **Corollary:** always report the instrument's own totals beside the verdict.
* **The ORACLE can be the deviant party.** SkyRoads' entire claimed frame-1115 frontier was a
  contaminated oracle with the candidate correct: `install_replacements=False` gated the hooks
  IMPORT, not the installation, so 29 replacements including a deliberately behaviour-changing
  loop-skip optimisation ran on the "pure-ASM oracle". Before localizing a divergence inside the
  candidate, PROVE the reference side is the original program — `dos_re.hooks.assert_pure_oracle`
  exists for exactly this.
* **A fail-quiet limit is indistinguishable from a passing measurement.** Both harnesses returned
  silently on step-budget exhaustion, leaving a truncated oracle that still looked authoritative.
  Prefer raising over returning.
* **The earliest VISIBLE divergence is not the earliest divergence.** OVERKILL frame 882 (52 video
  bytes) was a consequence of a ONE-BYTE state divergence at frame 870. Widen the observable before
  concluding.
* **The CPUless import guard is PROCESS-GLOBAL.** Use `overkill.cpuless_host.import_guard()`
  (scoped). A bare `install_import_guard()` cost 239 red tests that each passed in isolation.
* **`pathlib.read_text()` defaults to cp1250 here** — always pass `encoding="utf-8"`.
* **Backgrounded runs write output only at exit.** An empty log is NOT evidence of a hang; check
  `ps -W`. Use `-u` and the heartbeat.

## 7. dos_re — what landed this milestone (all game-agnostic)

* **setjmp/longjmp** (`emit_cpuless`): `mov sp,m16` falling into a `ret` is a terminal NON-LOCAL
  EXIT (fail-loud raise, no exit ABI, depth walk stops); the paired `mov m16,sp` SAVE is permitted
  because the ABI keeps `sp` exact. The unwind is deliberately NOT modelled. A later fix made the
  recogniser refuse a tail with a non-returning path (a spin-wait is real behaviour, not an abort).
* **Oracle purity** (`hooks`, `runtime`, `player`): `registry.uninstall(cpu, keep=)`,
  `assert_pure_oracle(cpu, allow=)`, and `create_runtime(install_replacements=False)` honoured via a
  POST-BOOT STRIP (order-independent; guarding the import does not work).
* **The shadow rung** (`lift/shadow.py`): generalised out of skyroads. The candidate is a DROP-IN
  with the generated signature, so comparison is TOTAL by construction — every output, flags, fmask,
  cost, ordered memory writes. Exemptions require a written reason or they raise. Verdicts use the
  `Verdict` lattice (MISMATCH < INTERNAL_ERROR < INCONCLUSIVE < VERIFIED, aggregated by min).
  **An override never called is INCONCLUSIVE, never VERIFIED** — this caught a vacuous control on
  day one. The candidate gets a `_NoEffectPlat` whose every attribute raises.
* **Manufactured return** (`emit_cpuless` + `cfg`): `push addr ; jmp indirect` is a CALL, not a
  tail. Needed a CFG fixpoint — the pushed address is a control-flow ARRIVAL, and `scan_function`
  was stopping there. Census cost zero (623/626 both ways).

**Rule for this milestone:** anything game-agnostic goes INTO dos_re so the other game inherits it.
But "general" must be MEASURED, not assumed — the setjmp/longjmp shape appears in zero other lifted
corpora (skyroads 9,245 instructions, lemmings 22,739). It belonged in dos_re because the CONSTRUCT
is general, not because the other ports needed it.

* **Not absorbable, recorded not routed around**: `1B49`/`3B17` do `inp/outp(0x61)` on the PC

  speaker twice per confirm while every compared observable agreed and the verdict read VERIFIED.
* **`41A0`**: self-modifying (writes its own threshold to `cs:41E9`), and its middle count comes from
  `ss:[0x9612]` not `ds` — equal here, so a ds-based body would agree on every real call and still be
  wrong. Costed and declined.
* **`3A96`**: VERIFIED label overstates it — the checker covers 1 of 8 segments.
* **`32C1`/`33FD`/`38BF`**: zero calls in any demo. Unexercised is unprovable.
* **Open**: demo BREADTH (the 5109-frame demo has zero input events, so it proves the attract path);
  and the xdist race — `build_recovered.py` `rmtree`s the live corpus while another worker may import
  it. Patched with a lock covering the two colliding tests. The proposed temp-dir-and-swap fix does
  NOT work: `os.replace` won't swap a non-empty directory on Windows, and CPython caches a
  `FileFinder` per directory so a stale listing survives any swap. The real invariant needs a
  cross-process reader-writer lock.

## 9. TOOLING / SPEED

* **PyPy for oracle-heavy differentials** (~10x): `pypy3 -u scripts/verify_cpuless_coldstart.py`.
  Proven byte-identical to CPython **including on FAILING runs** (overkill 900-frame diverging case,
  logs sha1-identical). Future PyPy upgrades must be A/B'd against a *diverging* case, not a passing
  one.
* **CPython + `-n auto` for SUITES, not PyPy** — every PyPy worker re-pays JIT warmup.
* **Snapshot AT THE WEDGE.** Turns a 5-minute replay into an instant `lindis.py` run.
* `decode_one(fetch_callback, ip)` takes a CALLBACK, not `(mem, cs, off)`. See `scripts/lindis.py:61`.
  For a one-off decode, just run `lindis.py` — it is in the registry.

## 10. STANDING RULES (non-negotiable)

* Never commit red; full suite + lint green before every commit.
* One verified slice = one focused commit + push.
* **Never weaken an oracle/test/assertion/checker to make a slice pass**, and never shrink the
  compared region to make a diff go away. If a test's premise became obsolete, re-point it at a
  still-true premise; never delete or relax it.
* **Do not guess contracts, timing, control flow, alignment, or observable outputs.** The original
  game is the authority. Measure.
* Fail loud, never fake a gap, never report a result you did not observe.
* Failed attempt ⇒ full revert + a repro line in `loop_blockers.md`.
* Check the STANDING MECHANISMS registry at the top of `run_status.md` before building any tooling.
* **State claims NARROWLY** — "proven for this demo, to this frame". A promoted corpus is not a
  running game; closure is not execution.
* Prefer refusing over guessing: turning silent wrongness into a loud refusal is a WIN even where it
  does not become correct handling.
